# 로드맵

기한을 따로 두지 않고 완성과 학습을 목표로 길게 가요. 첫 목표는 **2월 첫 주(설 연휴 전) 데모**이고, 아래 주차는 대략이에요.

| 마일스톤       | 대략    | 끝났다고 보는 기준                                                         |
| -------------- | ------- | -------------------------------------------------------------------------- |
| M0 뼈대        | 1주     | 레포·CI·브랜치 보호, 앱이 탭 4개로 뜸, 공통 타입 합의 (관문 1)             |
| M1 각자 화면   | 2~4주   | 예시 JSON으로 각자 기능 화면이 끝까지 돌아감                               |
| M2 데이터 연결 | 5~7주   | 로그인, 테이블·RLS, 메모 → 카드 제안 → 확인 저장                           |
| M3 핵심 흐름   | 8~11주  | 메모 → 카드 → 업무일지 AI 초안, 구글 일정 → 시간 잡기 → 수행 확인 (관문 2) |
| M4 데모        | 12~14주 | 학습일지로 팀 내부 사용, 버그 수정, 발표 준비                              |

관문 1을 통과해야 병렬 개발(M1)로 넘어가요. 약속이 흔들리면 각자 만든 화면이 나중에 안 맞기 때문이에요.

## 담당

| 담당 | 영역          | 기능 폴더                     | 공유 영역                              |
| ---- | ------------- | ----------------------------- | -------------------------------------- |
| A    | 기록·문서     | notes, sessions, editor       | 세션 템플릿 JSON                       |
| B    | AI·카드       | cards, ai-draft               | extractor, ai-client, 추출 테스트 세트 |
| C    | 캘린더        | calendar, execution           | `supabase/functions/google-calendar`   |
| D    | 기반·공유, PM | settings, feed(P1), 탭·라우팅 | ui, storage, lib/, .github, CI         |

## M0: 모두 함께 (1주)

- [ ] D: GitHub 레포 세팅 ([setup-github.md](setup-github.md)), Supabase 프로젝트 만들기, `.env` 값 공유 방법 정하기
- [ ] 모두: 각자 폰에서 앱 실행해 보기 (`pnpm dev` → Expo Go)
- [ ] 모두: `packages/shared`의 타입과 예시 JSON 리뷰. 고칠 점은 `contract` PR로 (관문 1)
- [ ] 모두: 학습일지(`docs/learning/`) 첫 기록

## M1: 예시 JSON으로 각자 화면 (2~4주)

각 기능 폴더의 README에 자세한 할 일이 있어요.

- **A**: 막 쓰기 입력창과 최근 메모, 세션 목록(템플릿 JSON), 단순 편집기
- **B**: 카드 목록과 확인·고치기·버리기, 카드 고르기 → 가짜 초안 화면, 추출 테스트 세트 20개
- **C**: 캘린더 일·주 보기, 시간 후보 3개 화면(가짜 계산), 수행 확인 시트
- **D**: 설정의 AI 키 저장, 로그인 방식 결정(결정 기록), 테마 정리, 파일 버킷 설계

## M2 ~ M4: 큰 줄기

- **M2**: D가 로그인·`profiles`·RLS 기본값을 먼저 열고, 각자 자기 테이블을 만들어 예시 JSON을 실제 데이터로 바꿔요. B는 규칙 추출을 테스트 세트로 검증해요.
- **M3**: B가 Claude 어댑터와 AI 추출·초안을, C가 구글 캘린더 함수와 시간 잡기 저장을 만들어요. 수행 확인 결과가 업무일지 초안에 들어가면 관문 2예요.
- **M4**: 학습일지로 팀이 직접 써 보고, 불편한 점을 이슈로 올려 고쳐요.

## 미룬 것 (P1 이후)

녹음·받아쓰기(담당 미정), 검색·그래프, 공유 피드, 슬랙·노션 수집, 중복 카드 합치기, 사람 이메일·별칭 정리, 물어보기, 주간 회고, 오프라인 동기화, NestJS 서버

## 회의

- 정기 회의: 매주 일요일 오후 8시. 빠진 사람이 다음 회의 일정을 잡아요.
- 순서: 지난 목표 확인 → stage 빌드로 데모 → 주요 버그 → 다음 회의까지의 목표. 마일스톤이 끝난 회의에서 stage를 main에 합치고 태그를 붙여요.
- 담당끼리 부딪히는 일은 정기 회의를 기다리지 않고 자유 회의로 풀어요.
