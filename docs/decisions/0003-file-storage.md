# 0003. 파일 저장소는 Supabase Storage로 시작, S3 전환 대비

- 날짜: 2026-10-26
- 상태: 채택 (인프라 계획: 서현)

## 결정

- 처음에는 EC2·S3를 직접 운영하지 않고 Supabase Storage를 써요. S3 프로토콜과 호환돼요.
- 업로드는 앱이 서명된 URL을 받아 저장소로 직접 보내요. 서버를 거쳐 올리지 않아요.
- DB의 `files` 테이블에는 파일 키와 메타데이터(소유자·크기·형식·상태)만 저장하고, URL은 읽을 때마다 만들어요.
- 저장소 호출은 `packages/storage`의 `FileStorage`로만 해요. 지금은 Supabase 어댑터, 나중에 S3 어댑터를 환경 변수(`EXPO_PUBLIC_STORAGE_PROVIDER`)로 바꿔 끼워요.

## 전환 신호

- 저장 용량이 요금제 포함량을 넘어 계속 늘 때
- 다운로드 트래픽 비용이 커질 때
- 파일 처리가 Edge Function의 실행 시간·메모리 제한에 걸릴 때

요금과 한도는 바뀔 수 있어서, 전환을 검토할 때 Supabase 공식 문서에서 다시 확인해요.
