# 0001. 서버는 3단계로 도입하고 Expo + Supabase 직접으로 시작

- 날짜: 2026-10-26
- 상태: 채택

## 배경

팀원 모두 앱 개발이 처음이에요. 처음부터 앱, NestJS 서버, Supabase, 오프라인 동기화를 모두 다루면 배울 게 너무 많아요.

## 결정

- 앱은 Expo(React Native) + TypeScript로 만들어요.
- 서버는 단계적으로 도입해요.
  1. **지금**: 앱이 Supabase(로그인·DB·파일)에 직접 붙어요. 서버 코드가 없어요.
  2. **비밀키가 필요해지면**: Supabase Edge Functions (구글 캘린더 연동 등)
  3. **기능이 커지고 익숙해지면**: NestJS 모듈로 옮겨요. 기능 폴더 구조는 그대로라 옮길 때 혼란이 적어요.
- 처음에는 미뤄요: 오프라인 동기화(온라인 전용으로 시작), OpenAPI·목 서버(TypeScript 타입 + 예시 JSON으로 시작), 슬랙·그래프·녹음

## 다른 선택지

- Flutter: 한 코드로 Android·iOS가 되는 건 같지만, 웹·TypeScript 생태계와 AI 도구 지원을 고려해 Expo를 골랐어요.
- 처음부터 NestJS: 구조는 깔끔하지만 첫 화면이 나오기까지 오래 걸려요.
- Firebase: Supabase가 SQL·RLS로 데이터 구조를 배우기 좋고, 나중에 Postgres를 그대로 가져갈 수 있어요.

## 결과

- 화면과 데이터부터 빨리 만들 수 있어요.
- 모든 테이블에 RLS를 반드시 걸어야 해요. 앱에서 DB에 직접 붙기 때문이에요.
- 서버가 필요해지는 신호: 비밀키가 필요한 연동이 늘거나, 여러 테이블을 한 번에 바꾸는 로직이 복잡해질 때
